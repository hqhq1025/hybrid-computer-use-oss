## Rebase mechanism and initial checks

This candidate reapplies only `d273308` onto main. Between consecutive
untargeted keypress, type, or scroll steps, AX requests a window-root read.
The provider still settles and reads the window inventory. A changed logical
window still stops the next input. Reads before targeted actions, waits,
and the final input remain full. Two-input batches gain no reduced read.

The service marks root-only observations and excludes them from element
comparisons. It retains the previous same-window ref map for the next full
read. Final evidence and screenshots follow the existing observation mode.
Selection actions do not qualify for reduced reads.

The change can reduce provider work in long keyboard batches. It cannot
reduce the model calls needed to plan those batches. Evaluation should count
eligible batches and reduced reads, compare provider time, and retain total
steps, tokens, cost, completion, and error rates. Earlier candidate panels
used a different baseline and do not establish a gain against current main.
